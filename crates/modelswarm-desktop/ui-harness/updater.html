Auto-update status line stub harness

Loads the REAL ../ui/index.html into a same-origin 1152×648 iframe with a stubbed window.__TAURI__ bridge, then checks the update status note (owner request 2026-10-12: "clients update and restart when we ship a new client"; Help-menu item since the 2026-10-15 nav-menu reorg — the note opens with the Help dropdown, which the harness clicks open behaviorally before measuring): the daemon-provided updater.line renders VERBATIM in every phase — available → downloading → ready/restarting, the two failure edges (check failed / install failed with the running version intact), and the dev opt-out — a missing payload degrades to the placeholder without breaking anything else, and neither the navbar nor the open Help dropdown overflows the app's default window. The status machine itself (transitions, terminal Ready, ignored stale events, env opt-out) is pinned by the Rust unit tests in src/app/updater.rs; this harness pins the render contract.

Run: serve the crate root over http — e.g. python -m http.server 4817 from crates/modelswarm-desktop — then open http://127.0.0.1:4817/ui-harness/updater.html. Opening from file:// cannot work (the harness fetches the UI same-origin).
