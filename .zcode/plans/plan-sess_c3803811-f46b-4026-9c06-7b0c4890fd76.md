# Phase H — Real-model Windows client: installer + model + live UI

Goal: an NSIS installer for a ModelSwarm desktop app that, on several test machines, downloads and verifies one pinned real model (Qwen2.5-0.5B-Instruct Q4_K_M GGUF), lets the user flip "start sharing" (hosting), and offers one function — a chat box that runs through the swarm stack. Decisions locked: Qwen2.5-0.5B-Instruct Q4_K_M; first-run download per ADR-008 (installer stays small, bundles only the pinned llama.cpp engine).

The codebase already has most of the skeleton: an HTTP `LlamaCppAdapter` runtime (schema-v2 manifests only accept `runtime.name="llama.cpp"` — no ADR-021 conflict to invent a new engine), tracker admin endpoints for candidate→promote, the desktop state-model UI, and NSIS notes. What does not exist: engine supervision, weight download/verify, live IPC, the real profile, the installer build, client-side catalog signature verification.

## H1 — Pin engine + register the real profile

- Pin a stock llama.cpp CPU-x64 release (`ggml-org/llama.cpp` `llama-bNNNN-bin-win-cpu-x64.zip`); record build id + `sha256(llama-server.exe)` in a `runtime-pins.json` at repo root. This hash becomes the manifest `runtime.build_hash` (ADR-008: engine bundled in installer; weights never bundled).
- Fail-closed resolver script (`scripts/resolve-candidate.mjs`, Node, no deps beyond what tracker already uses): resolves HF repo commit (40-hex), `sha256(GGUF)` via streamed download, `tokenizer_hash`, `chat_template_hash` (sha256 of the template string), and `architecture_hash` — whose key subset gets **defined here** (architectures, hidden_size, intermediate_size, num_hidden_layers, num_attention_heads, num_key_value_heads, vocab_size, max_position_embeddings, rope_theta, tie_word_embeddings, torch_dtype). Emits the schema-v2 manifest + derived `msp1:` id. No guessed hashes — any unresolvable input aborts (ADR-011).
- Register against production tracker (`POST /api/v1/admin/catalog/candidates` then `promote`, admin token from Vercel env) with `speculative_capabilities: ["proposal_tokens"]`, `decoding_abi_version: 1`.
- No schema changes → no new golden vectors. Document HF-URL derivation (`hf_repo` + `hf_revision` + `artifact_hashes[].path`) in new **ADR-022-real-profile-registration** (also records the architecture-hash subset). ADR-021 gets its decision appended: Accepted — beta engine is the pinned unforked llama.cpp server + existing HTTP adapter; perf-research options unchanged; still no performance claims.

## H2 — Artifact subsystem (download + verify + catalog trust)

- New module in `modelswarm-node` (or small crate `modelswarm-artifact`): streamed HF download to temp file with progress events (bytes/Content-Length), disk-space preflight, atomic rename to `%LOCALAPPDATA%\ModelSwarm\models\<profile_id>\<filename>`, streamed SHA-256 verified against the manifest, re-verify on startup (possession model, ADR-011).
- `modelswarm-store`: new `artifacts` table (profile_id, path, sha256, bytes, state, verified_at) + migration.
- Tracker client: verify the catalog envelope's Ed25519 signature against the pinned hub pubkey (`apps/tracker/keys/hub-public.hex` baked into the client build; rotation = re-release, noted). Currently only lease tokens are verified client-side.
- Model selection in the UI comes from the verified catalog — one profile listed (the Qwen one).

## H3 — Engine supervision + adapter completion

- Sidecar supervisor in the node: spawn pinned `llama-server.exe --model <gguf> --host 127.0.0.1 --port <ephemeral> --no-webui` (+threads/ctx flags), poll `/health`, restart-on-crash policy, kill on node shutdown. Binary located next to the app exe (installer resource) with env override for dev.
- `LlamaCppAdapter` completions: (a) `build_hash` from pinned engine; (b) `propose()` implemented as greedy self-continuation (draft = target, unmodified llama.cpp — the ADR-021 "unforked salvageable subset"); (c) determinism contract: `SamplingParams::default()` maps to temperature 0 (greedy) — required by the greedy E2E contract; explicit user sampling passes through in single-local chat; (d) real measured `metrics()` (nonzero decode rate — the rtt-spike fallback depends on it); (e) integration test gating the token-id recovery approximation (tokenize∘detokenize roundtrip over real vocab samples; if unstable for spec modes, cooperative mode is disabled for this profile and single modes ship — honest fallback).
- `NodeConfig`: engine path, model path/profile wiring; runtime-less nodes keep the honest 503 `no_peer` path.

## H4 — Desktop app: live UI + one function

- Desktop links `modelswarm-node` **in-process** (no child process): `Node::start` on Tauri's tokio runtime; supervision = task + restart.
- IPC commands (G1 audited surface + chat): `get_status`, `set_hosting`, `list_models`, `download_model` (progress via Tauri events), `send_chat`, `drain`. Only G2 state fields cross to the webview — keys/tokens/lease secrets never do (same process, enforced by command return types).
- `ui/index.html` stays the zero-framework page, now with vanilla JS: (1) **Setup/first-run**: tracker URL (default `https://modelswarm.deepflux.space`), privacy gate (first-run banner becomes an accept, persisted via existing license-acceptance table), model download card with progress bar + sha256 state; (2) **Hosting**: the static toggle goes live — register/heartbeat/lease/capacity-class now real; (3) **Chat** ("access the swarm"): one input + transcript; each reply gets an honest badge — mode (local single / remote single / cooperative), peer count, measured tok/s, fallback events. All existing G2–G4 elements (peers table, degraded chips, eligibility) flip from static to live.
- Gateway stays available on 11435 for OpenAI-compatible external tools; UI chat goes through in-process IPC (CSP stays `self`).

## H5 — Installer, CI, site

- `tauri.conf.json`: bundle `llama-server.exe` as resource; NSIS per-user config + `-internal-test-unsigned` version suffix + splash label (per staged nsis-notes; signing remains a recorded STOP).
- New CI job `desktop-installer` (workflow_dispatch + on-request): fetch pinned llama.cpp zip → sha-verify → `cargo tauri build` (tauri-shell feature wiring solved here) → upload `ModelSwarm_<v>_x64-setup.exe` + SHA256SUMS → publish to `apps/tracker/public/downloads/` + update landing page card (now offering installer + CLI exe) → Vercel deploy.
- Separate env-gated `real-model-e2e` job (workflow_dispatch): downloads the real GGUF on a windows runner and runs the H3/H4 integration tests (roundtrip, greedy parity single vs spec-loopback, chat smoke). Default CI stays fast and offline.
- Existing suites (271 Rust / 81 tracker tests, clippy `-D warnings`, fmt) must stay green; no ADR-019 mock labels weakened.

## H6 — Verification + docs

- `docs/acceptance/phase-h.md` + `docs/verification/phase-h.md`: live evidence — catalog signature verify on client, download-integrity (tamper test fails closed), engine supervision restart, chat through all three modes on loopback multi-node sim, installer produced + silent-install smoke, cross-machine test checklist for you (same LAN or VPN — no relay deployed yet, direct-connect failures must surface as the documented degraded state).
- ADR-021 decision note, ADR-022, README (client section), deployment doc gains an artifact-publication section.

## Order of execution

H1 (pin + resolver + register) → H2 (artifacts + catalog trust) → H3 (supervision + adapter) → H4 (desktop live UI + chat) → H5 (installer + CI + site) → H6 (docs/evidence). Each stage lands with tests green and a commit; the production tracker gets exactly one new active profile at H1 promote time.

Known honest limits, stated up front: unsigned binaries everywhere (labeled); LAN/direct-connection only (no relay); cooperative mode ships only if the token-id fidelity gate passes, else single modes; no performance claims anywhere.
