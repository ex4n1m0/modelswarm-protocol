## 1. Qwen2.5-7B gateway failure — root cause and fix

**Symptom.** Every chat request to the local gateway for the 7B profile
returned `no_eligible_peer` (retryable) while the same engine answered
templated curl probes directly. The executor's catch-all
`Err(_) => Retryable` swallowed the real error (commit 5642224 part 1
surfaces it: eprintln + peer_hint).

**Real error.** `malformed runtime response: generated token bytes [] not
in the pinned vocabulary`.

**Cause.** `decode_step` recovered the sampled token id exclusively from
`logprobs.content[0].bytes`. llama-server b11407 reports special tokens
(EOS, `<|im_end|>`) with `token: ""` and `bytes: []` — an empty byte
sequence that can never be in the bytes→id map. Every Qwen2.5 reply ends
in `<|im_end|>`, so every reply died at its final token. Empirically
confirmed against a live b11407 Vulkan engine (135M forced-EOS prompt):
`{"id": 2, "token": "", "bytes": []}`.

**Fix** (commit 5642224, `crates/modelswarm-runtime/src/llamacpp.rs`):
prefer the server-reported `logprobs.content[].id` (exact by
construction — the server samples from the same sha-verified artifact),
keep the bytes map as fallback, and fail closed with a loud
`token id disagreement` if both recoveries exist and disagree
(vocab-drift tripwire).

**Evidence.**
- `cargo test -p modelswarm-runtime`: 17/17 including two new regression
  tests (`special_token_with_empty_bytes_recovers_id_from_server`,
  `server_id_disagreeing_with_bytes_map_fails_closed`).
- Live: the same gateway request that failed now returns
  `"Hello!"` `finish_reason=stop` (completion_tokens 2 — one text token +
  the recovered EOS), engine b11407 vulkan, 2026-10-08 ~13:20 UTC.

## 2. F2a — circuit-relay v2 host with stream-carrying limits

**Deliverable.** `crates/modelswarm-relay` (commit a8d8a63): standard
rust-libp2p 0.57 relay (QUIC) per ADR-014 and the phase-f research:
reservations 4096 (8/peer), circuits 4096 (128/peer), circuit
duration/bytes uncapped, anti-abuse creation rates kept at library
defaults. Persistent key file → stable relay PeerId → stable
`/p2p/<relay>/p2p-circuit` addresses across restarts. Content-blind by
construction (forwards opaque substreams; lease gating stays at serving
peers per ADR-026).

**Three non-obvious requirements the integration test caught** (each
silently breaks reservation otherwise):
1. `max_circuit_duration` must be `Duration::from_secs(u32::MAX as u64)`:
   the wire format's duration field is u32 seconds and `u64::MAX` PANICS
   the behaviour while announcing the limit mid-reservation.
2. `set_status(Some(relay::Status::Enable))` must be forced — fresh
   relays start HOP-disabled until identify observes an external address.
3. The relay must `add_external_address(...)` — clients reject
   reservations whose response carries no relay addresses
   (`NoAddressesInReservation`).

**Evidence.**
`cargo test -p modelswarm-relay` (2 tests):
- `limits_carry_streams_and_scale_reservations` (config contract)
- `standard_clients_reserve_and_circuit_through_the_relay`: in-process,
  real QUIC over 127.0.0.1 — relay swarm + two standard relay-client
  swarms; client B reserves (accepted, limits on the wire:
  `duration: 4294967295s`, `data_in_bytes: u64::MAX`), client A circuits
  to B (`relay circuit A -> B`, `InboundCircuitEstablished`), ping data
  flows BOTH directions through the relay. ~2s runtime, green twice.

**Deployment (owner's decision: relay runs on their second desktop).**
`OneDrive Desktop/ModelSwarm-relay/`: `modelswarm-relay.exe` (release),
`RUN-MODELSWARM-RELAY.bat` (UDP 4001, persistent key beside the exe,
firewall-allow note). Internet-facing use additionally needs the router
port-forwarded to that machine's UDP 4001 — LAN use needs nothing.

**Honest boundary.** This proves the RELAY side. MSP nodes cannot yet
USE it: our transport opens raw QUIC streams without multistream-select,
while RESERVE/HOP are negotiated protocols — the F2b node-side client
(reserve + `/p2p-circuit` dial over the session layer, hand-rolled
multistream-select + hop protobuf or a swarm-based upgrade) is the next
work item. The relay is interoperable with standard libp2p clients today.

**Gated LAN re-probe** (lease earn + enforce both sides, pooled
connection): blocked on machine B being offline; rerun
`lan_cross_machine_completion` per the recorded env/command once B hosts
again. The 7B gateway fix in this session removes the last known
blocker on A's side.
