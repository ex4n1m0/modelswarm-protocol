# MSP Cooperative v1 — session-negotiation namespace (created by ADR-029)

Status: created 2026-10-09 by ADR-029 (owner-approved gate D3/D18). Additive
to msp-v1 and **frozen on the same terms**: changes require an ADR; no
implementation may invent fields outside this document, `protocol/msp-v1.md`,
or `catalog/schema*.json`. `protocol/msp-v1.md` and
`protocol/messages.proto` remain **byte-identical** — nothing here edits
them.

## 1. Scope

This is the home for cooperative session negotiation: `SessionOffer` and the
preset enum. It is deliberately minimal. The multi-peer message vocabulary
(`SpecMessage`: prefix commits, rounds, cooperative receipts) remains a
Rust-implementation namespace (`/msp/cooperative/1.0.0`,
`crates/modelswarm-session/src/spec.rs`) until its own future ADR freezes it
here; when that ADR comes, it must bind protocol version, nonce, and
deadline into every state-changing signed payload (the architect-recorded
gap).

Transport and framing inherit msp-v1 §6 (QUIC + Noise, request-scoped
streams). This namespace carries no prompt or completion content beyond
what the §6 stream already carries; the hub never sees any of it.

## 2. SessionOffer (the only wire addition authorized by ADR-029)

Sent by the requester at cooperative session open, before any cooperative
traffic. Canonical JSON per msp-v1 §2.2; snake_case fields.

```json
{
  "session_id": "<opaque unique string, generated by the requester>",
  "protocol_version": "msp-cooperative-v1",
  "preset": "fast | balanced | deep | verified | maximum",
  "budget": {
    "max_endpoints": 1,
    "max_endpoint_seconds": 120,
    "max_output_tokens": 2048
  }
}
```

| Field | Type | Meaning |
|---|---|---|
| `session_id` | string (frozen) | Correlates offer, accept, and receipt across multiplexed sessions; unique per offer; echoed by SessionAccept and carried by the ReceiptV2 |
| `protocol_version` | string (frozen; `"msp-cooperative-v1"`) | Binds every cooperative wire message to its namespace version (state-changing messages carry their version — architecture-seat review condition, 2026-10-09) |
| `preset` | enum (frozen; exactly the five ADR-029 values) | The negotiated contract tier. The ONLY mode-ish field on the wire. Primitive-mode resolution is planner-internal (§4) |
| `budget.max_endpoints` | u32 ≥ 1 | Cohort-size cap inside the preset envelope; the planner still picks the smallest useful cohort |
| `budget.max_endpoint_seconds` | u64 ≥ 1 | Summed wall-seconds the session may spend across peers |
| `budget.max_output_tokens` | u32 ≥ 1 | Output-token ceiling for the session |

Budget numbers above are **initial values, tunable, R0.5+
measurement-informed** (retuned after the 9.6 pass-1 result); the field set
and the enum are frozen. The requester MAY offer lower budgets than the
preset's default; never higher (the serving side clamps down, never up).

## 3. SessionAccept (the reply)

```json
{ "session_id": "<echoed>", "protocol_version": "<echoed>", "preset": "<echoed>", "budget": { …effective, clamped-down budget… } }
```

A peer that cannot honor the preset (components not gated, budget
infeasible) rejects the offer; the requester then falls back to the msp-v1
§6 single stream (`fast` semantics) — fallback is mandatory and never
silent. No primitive-mode field appears in either message.

## 4. Mode-resolution recording

Which primitive modes actually executed, the cohort, and the budgets spent
are recorded in the **receipt** (receipts v2, ADR-030:
`preset`, `mode_id`, cohort, endpoint-seconds, accepted/verified tokens).
Recording lives in the receipt — not on the offer/accept wire — so planner
internals stay internal while every result stays explainable.

## 5. Frozen-namespace constraints (what is breaking, and forbidden)

- Adding `preset`/mode fields to msp-v1's frozen `InferenceRequest` or
  `Handshake` (§6.2) — breaking; forbidden.
- Editing `protocol/messages.proto` field numbers, or any msp-v1 frozen
  field — forbidden (byte-identical).
- Overwriting the msp-v1 §7 receipt shape in place — forbidden; receipts v2
  is a NEW signed object with its own golden vectors.
- Changing `JobResultSchema.intake` semantics on the tracker — forbidden.
- Prompt/completion content anywhere in this namespace — forbidden
  (content-blind).

## 6. Preset tier table (governed by ADR-029; mirrored for implementers)

| Preset | Primitive modes allowed | Cohort cap | Correctness label | Extra disclosure |
|---|---|---|---|---|
| `fast` | `single` | 1 | lossless (the baseline) | none beyond today's |
| `balanced` | `single`, `hedged` (honesty-patched) | 3 | lossless | recipient set = raced peers |
| `deep` | `balanced` + `best_of_n` + deliberation roles | per budget | approximate — never lossless | recipient set + roles + compute budget |
| `verified` | `balanced` + `audited` chain | per budget | detection-oriented; carries audit proofs | auditors see canary-class tasks |
| `maximum` | HYBRID = composition of individually-gated modes only | per budget | union of component labels | full composition + budgets |

`fast` is default and live; other tiers light up exactly when their
component modes pass their existing gates (M10 build order, item 11). Each
tier's recipient-set disclosure updates `docs/privacy.md` wording when it
lights up (ADR-029 §3).

## 7. Vectors

A cross-language golden vector for the preset enum serialization and the
`SessionOffer` canonical form is required in `protocol/vectors/` before any
second implementation (TS or otherwise) reads this namespace.
