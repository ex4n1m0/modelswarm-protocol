# v0.2.23 release notes — 2026-10-13

**The pairing milestone release.** Earlier today the first live family
pairing between two real machines (Windows, vulkan, Qwen2.5-7B) was
CONFIRMED in BOTH directions — `pairing_confirmed` 8/8 each way, verify
passes 28–318 ms — with one failure root-caused live along the way: a
warm prompt cache flips the sidecar's first greedy draft token
(0/8 divergence-at-0 against a cold verifier; both cold-drafted rounds
confirmed). v0.2.23 ships the fix for that and turns pairing on by
default.

## What's new

- **Family pairing ON by default.** The serving listener and the family
  verify engine now start with hosting — no env var, no button. A
  persisted settings toggle ("allow swarm pairing", Setup section,
  default on, applies at next hosting start) replaces `MSP_LISTENER`
  entirely. An honest RAM/VRAM check projects the verify engine's second
  copy of the model weights against the 70% ceiling and degrades with
  the exact numbers if it would breach (advisory until the resource
  governor owns enforcement).
- **Drafts are self-verified before they leave the machine** (today's
  root cause, fixed): every drafted pairing window runs through a fresh,
  cache-cold local verify engine first. A warm-cache flip — or any local
  inconsistency — is caught locally (`local_selfcheck`) and never sent;
  a missing local engine fails closed (`selfcheck_unavailable`).
- **Pairing failures now say why in the log.** The exact failure detail
  (`rejected`, `io`, `local_selfcheck`, …) reaches the
  `family.probe.pairing` telemetry event; previously it existed only on
  the screen (found live during today's pairing debug).
- **Chat controls (the language-drift escape hatch):** a clear-chat
  button (resets the conversation without restarting the app) and a
  temperature slider (default 0 = greedy; applies to chat replies only —
  pairing/verification stays greedy, its determinism contract).
- **Peer-first model picker:** when any model in the catalog has live
  peers, only those are shown (your downloaded/selected models stay
  visible); everything else hides behind "show all N (x more)".
- **Chat auto-engage groundwork (honest boundary):** every swarm chat
  turn now evaluates the family engage gate (the never-worse rule) and
  reports the outcome per reply — `family: not engaged (reason)`.
  Routing chat content through family sessions remains protocol-blocked
  by design (the family wire is content-blind); lifting it is the
  owner-gated rule-8 commitment path (ADR-034).

## For testers

This is the first release your machines pick up **through the built-in
self-updater** (6-hour checks + on start, minisign-verified against the
build-embedded key, passive restart-to-install). If you are on 0.2.22,
just leave the app running.

Standing honesty notes: installers remain unsigned (code-signing
decision pending — SmartScreen reputation false positives are expected
on first download); family pairing needs the engine bundle and
direct/LAN connectivity (no relay yet); prompts and completions never
reach the tracker and are redacted from all logs.
