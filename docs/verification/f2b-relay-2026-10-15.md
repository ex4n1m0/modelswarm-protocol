# F2B relay deployment record — 2026-10-15

The owner-directed production relay (first public ModelSwarm relay), deployed
by the Integrator through the owner's Oracle Cloud account (owner-created
free-tier account, ap-singapore-1). This records the deployment facts, the
incidents, and the honest open posture. The first RELAYED cross-NAT family
completion (the F2B exit proper) lands here as an addendum when machine C's
firewall entry and the v0.2.25 client land.

## Deployment facts

- **Host**: Oracle Cloud `msp-relay` VM, ap-singapore-1, Ubuntu 20.04 x86.
- **Shape posture (honest)**: launched by the owner as VM.Standard3.Flex
  (paid; covered by the 30-day trial credits). The always-free shapes are
  capacity-blocked in-region at deploy time (VM.Standard.E2.1.Micro: "Out of
  host capacity"; VM.Standard.A1.Flex: 500/429 retried). A background retry
  loop hunts A1 capacity; on landing the relay migrates WITH THE SAME
  identity (key backed up) and the SAME reserved IP. Migration recorded here
  when it happens.
- **Address**: `152.69.218.106:4001/udp` (QUIC). RESERVED public IP (survives
  restarts — proven: the IP moved across a terminate+relaunch unchanged).
- **Relay identity**: `12D3KooWKwGxyw6tgndYTxjRRcNrQck3W2f3yuG483vxXaVqbCtZ`.
  Identity key persisted at `/opt/msp-relay/msp-relay.key` on the VM and
  backed up offline (Integrator machine, `~/.ssh/msp-relay-identity.key`).
  The FIRST deployment's key was lost with a terminate (no backup — that
  cost one PeerId rotation before anything referenced it; lesson: back up the
  identity key before any instance operation).
- **Service**: systemd `msp-relay.service`, `Restart=always`, enabled.
  Run line: `--listen 0.0.0.0:4001 --key /opt/msp-relay/msp-relay.key --public`.
- **Build**: from main @ 7cc1274 (`cargo build --release -p modelswarm-relay`
  on the VM; x86_64, stable).
- **Firewall posture (the D12 interim — see incidents)**: cloud security list
  allows TCP 22 (ops) + UDP 4001 from the OWNER'S HOME IP ONLY
  (180.94.131.44/32 — machines A and B), full egress; VM host iptables allows
  UDP 4001 (persisted). Machine C's source IP joins the allowlist when the
  owner provides it. This allowlist is SCAFFOLDING for gate D12 (relay has no
  authn/authz; per-circuit byte/duration caps exist in code but are not yet
  runtime-configurable) — NOT the product design. ADR-038 (relay admission
  tickets + frozen cap policy) closes D12 and the relay opens to everyone.

## Incidents (honest record)

1. **Self-inflicted SSH lockout**: the first security-list update was built
   from a corrupted capture (empty rules read as zero) and REPLACED the list
   with ingress=[udp4001] + empty egress — deleting SSH. Recovered via Cloud
   Shell (control-plane side-channel independent of the VM); the fix rebuilt
   the complete rule set. Lesson recorded: never apply a firewall update
   from an unverified capture; jq-verify the merged file AND the live get
   before update.
2. **Capacity reshuffle**: the always-free shapes unavailable at deploy time
   (documented above) — service restored on the trial shape rather than
   waiting; free-shape migration continues in the background.
3. **Terminal-channel corruption**: the Oracle console's accessibility
   terminal garbles long single-burst typing (dropped/doubled characters);
   chunked typing with per-chunk pauses and per-command verification is the
   reliable pattern. Two garbled commands executed malformed before the
   pattern was established (both no-ops).

## v0.2.25 ship addendum — 2026-10-15 (the D12 close, live-proven)

The relay release shipped (bump 330b96c → staging 96adf68 → deploy; the full
train record is the staging commit message + the rehearsal doc). This
addendum records the relay-side facts of the same evening.

**Relay binary rebuilt at ship time.** The VM was still running the 7cc1274
build — BEFORE the ADR-038 admission gate (13046f0) and cap flags (782d55a)
— which would have made the v0.2.25 client's admission protocol incompatible
on day one. Rebuilt on the VM from 330b96c (`cargo build --release -p
modelswarm-relay`, 59s), swapped with the old binary backed up, service
restarted 12:48:56 UTC. Same identity from the persisted key — PeerId
12D3KooWKwGxyw6tgndYTxjRRcNrQck3W2f3yuG483vxXaVqbCtZ UNCHANGED (relay.addr
on A+B stayed valid). Startup posture line: reservations=4096 / per-peer 8 /
circuits 4096 / per-peer 128 / 1800s / 16MiB per circuit, admission
ARMED (/msp/relay-ticket/1 pre-flight, fail-closed limiters, memory-only
state), content-blind, `--public`.

**First client reservation from outside the cloud — and the admission gate
proven live.** Machine A self-updated 0.2.24→0.2.25 via the updater at
13:38 UTC (log: updater.check → updater.install → before_exit → restart);
hosting engaged via the product switch. The relay journal shows the exact
ADR-038 sequence:

```text
13:42:56  reservation denied  12D3KooWHqHP… : ResourceLimitExceeded   (fail-closed: no ticket yet)
13:44:56  reservation denied  …
13:45:26  reservation denied  …
13:45:56  admission accepted  12D3KooWHqHP… until 2026-10-15T13:57:27Z   (tracker-minted ticket, via heartbeat)
13:45:56  reservation accepted by 12D3KooWHqHP…
13:46:59 / 13:48:18 / 13:48:39 / 13:56:09 / 14:03:18 / 14:03:39  reservation (renewed) by …
```

The denials are the design working: the gate refused unticketed reservations
until the production tracker (deployed with ticket minting at the v0.2.25
deploy, minutes earlier) supplied a heartbeat-fresh ticket, then accepted.
Circuit address bound on A: `/p2p-circuit/` via
`/ip4/152.69.218.106/udp/4001/quic-v1/p2p/12D3KooWKwGxy…`. Machine B
self-updated to 0.2.25 at 13:50:54 (MSPLaunchApp task); its relay.addr is
seeded and activates when hosting next engages there.

**D12 closed — the relay is open to everyone.** Console UI (the owner
cleared MFA at the terminal), Add-Ingress-Rule dialog — a SINGLE-RULE add,
never the replace-all update that caused the lockout incident:

- NEW: `0.0.0.0/0 UDP 4001 "MSP relay open - D12 close ADR-038 admission tickets"`
- UNTOUCHED: `0.0.0.0/0 TCP 22 (SSH)`; egress `0.0.0.0/0 all protocols`
  (post-change live capture re-read from the console + SSH verified from the
  Integrator terminal + reservations continuing to renew across the change).
- The interim `180.94.131.44/32 UDP 4001` rule was LEFT IN PLACE deliberately:
  additive-OR, harmless, and removing it via the row menu risks the SSH rule
  for zero functional gain. Removable at the owner's leisure.
