# v0.2.22 release notes (2026-10-13)

All-OS release (one version bump; Windows NSIS, Linux deb + AppImage,
macOS arm64 DMG ship together). Engine pin unchanged: llama.cpp `b11407`
(sha256-verified per OS at build time; no model weights are bundled —
first-run download per ADR-008). Written by the Test and Release Engineer;
honest-wording rule applies — no aspirational claims, and no performance
numbers are cited at all (this release carries no new performance claims;
the standing provenance rule applies unchanged).

## What is new in 0.2.22

**The desktop app now keeps itself current: this is the last manual
install.** The app checks for updates on start and then every six hours,
downloads the package over HTTPS, verifies it with a minisign signature
against the public key built into the app at build time (the update
origin cannot cause an unsigned-by-us package to install — the signature
is verified client-side before anything is installed, and a version
mismatch between the signature and the manifest is rejected), and
restarts to install with a passive progress bar. The download is bounded
(10-minute overall timeout, 512 MiB size cap enforced mid-stream), a
failed update never blocks the app — the running version keeps serving
and the next check happens on schedule — and supervised engine processes
are stopped before the installer replaces files. The header shows one
honest status line at all times ("update available → v…", download
progress, readiness, or the exact failure). `MSP_NO_AUTOUPDATE=1` opts
out of checking entirely. Installers remain unsigned OS-level binaries
(code signing is still the separate G6 stop); update packages carry
their own signatures as described above. Until every tester runs this
build, updates still reach 0.2.21 installs only via manual download —
from 0.2.22 onward the app updates itself.

**The model picker now shows a live census per model.** Next to each
catalog entry the picker displays how many peers are currently hosting
that exact model (the same public, counts-only swarm census the website
shows; no identifiers, no content). A model nobody hosts yet is visible
as such, so a newcomer can pick the ones with company.

**A task-manager-style resource monitor panel** sits in the right column
below Privacy: CPU (process-tree percent), RAM (system percent + tree
working set), and GPU (utilization percent + VRAM), refreshed once per
second. Each field degrades to an honest "n/a" when the sampler cannot
read it. It is collapsed by default and covers the supervised engine
processes plus the app itself.

**One-click family pairing (ADR-034 tier 1).** Two peers hosting the
same exact model pair — same Hugging Face repository, revision hash,
file digest, quantization, and pinned runtime — can now pair
automatically: the serving side derives and pins a frozen neutral
prompt deterministically before it is ever read, the coordinator binds
to the same derivation, and the existing "test family pairing" probe
reports `pairing_confirmed` or `pin_mismatch` (with honest
`pin_unpinned` when the serving side has not opted in). No prompt
content crosses the wire — only counts and the pin's hash. This remains
OPT-IN and gated: the serving side must set `MSP_LISTENER=1` and have
the engine bundle; the family probe needs no relay and works only on
direct/LAN-reachable networks — we still claim no NAT traversal.

**Settings are no longer lost when the config file is rewritten.** A
latent bug made every tracker or model change rewrite `config.json`
from a two-field template, silently deleting every other setting
(window state, advisory config, anything written by a newer version).
The writer is now a read-modify-write over the full object: the two
daemon keys update, everything else survives verbatim.

## Unchanged for everyone else

Everything shipped in 0.2.21 behaves the same: single-host chat,
msp-v1 P2P swarm serving behind the lease gate, ADR-032 cooperative
batched speculative verification behind its opt-in gates, hosting
challenges, heartbeat/lease lifecycle, the OpenAI-compatible loopback
gateway, and the tracker. Users who never opt into the family path or
the census UI run exactly the prior behavior. (Internal: the release
additionally hardens the updater's download phase with the bounded
download above — see `docs/reviews/review-updater-security-2026-10-13.md`
— and ships a non-Windows compile gate for the C-API adapter introduced
with 0.2.21.)

## Installers (staged with this release)

`ModelSwarm-Setup-0.2.22-windows-x64.exe`,
`ModelSwarm-0.2.22-linux-amd64.deb`,
`ModelSwarm-0.2.22-linux-amd64.AppImage`,
`ModelSwarm-0.2.22-macos-arm64.dmg` — sha256 manifest in
`apps/tracker/public/downloads/SHA256SUMS.txt`; direct URLs remain
`/api/download/<file>`. The AppImage is the self-updating Linux build;
the `.deb` stays a site-only convenience for humans (deb-managed installs
self-replace outside dpkg when they update). The update manifest
`/downloads/latest.json` ships with this release and is signed against
the built-in key (rehearsal record:
`docs/verification/updater-manifest-rehearsal-2026-10-13.md`). Site
deployment is a separate owner step (Vercel), not part of this release
train.

## Release-train obligations carried forward (RC-1, standing)

Every release train from now on signs each installer at owner-local
staging with `--app-version <VERSION>` (mandatory — clients reject
updates whose signature does not name the announced version), the
signing private key never enters the repo, CI, or logs, and key
rotation means shipping a new client with a new embedded public key
(a manual install; the old public key stays valid on deployed clients
for one full adoption cycle).
