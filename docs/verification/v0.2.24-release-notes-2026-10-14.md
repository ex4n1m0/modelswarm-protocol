# v0.2.24 release notes — 2026-10-14

**The true-swarm release.** Your conversation can now be verified across
the swarm, and the app gains an intelligent assistant — with one wall
that never moves: the swarm chat box is served by you and your peers,
never by a cloud.

## What's new

- **Family-verified chat (the true swarm).** An elected mode: your
  conversation — in a form the receiving computers can read — goes to
  every verification peer of the session, your own engine drafts, and
  the peers cross-check every committed word. **It is slower by design,
  not faster** — verification is the benefit, never speed. The hub
  (modelswarm.deepflux.space) never sees any of it. Both disclosures
  ship verbatim:
  - Serving side (on by default; you can turn it off in Setup and
    requesting peers are refused honestly): "This computer carries
    other users' conversations (as token ids it can read) through
    family verification. On by default — you can turn it off, and
    requesting peers are refused honestly when you do."
  - Requester side (your election, off by default): "Family
    verification ON: your conversation — in a form the receiving
    computers can read — goes to every verification peer this turn (N).
    It is slower than single-peer chat, not faster. The hub
    (modelswarm.deepflux.space) never sees any of it. Turn it off any
    time."
  Self-updaters acquire the default-on serving carriage with this
  release; a pairing mismatch is now a session-open reject
  (`pin_mismatch`), never a first-round surprise.
- **The assistant panel.** A separate, always-present help channel:
  hardware-aware model recommendations ("which model fits my machine"),
  installation and troubleshooting help grounded in the app's own honest
  status labels. It ships in static built-in-help mode by default; the
  cloud mode activates only where a DeepSeek key is configured locally
  AND the one-time disclosure is acknowledged ("sends what you type
  here, plus facts about your machine and setup — never your swarm
  chats… advice only"). Opt out in Settings with zero functional loss.
  Every cloud reply carries the provenance chip: "Cloud assistant —
  advice only; this app's rules decide."
- **The chat wall (structural, tested).** No completion path anywhere
  can reach the advisory client — dependency direction, enumerated call
  sites, and data walls are enforced by tests in CI; your swarm chats
  can never leak into the assistant (canary-tested both ways).
- **Under the hood:** the enforced memory governor admits (or honestly
  refuses) family sessions by real RAM/VRAM ceilings; the telemetry
  vocabulary is fully inventoried in CI (91 events, every one declared);
  MSP_LISTENER and all env-var gates are gone (settings only); the
  installer build auto-triggers on version bumps; manifest signatures
  are verified by a rehearsal tool before every deploy.

## For testers

Installers remain unsigned by owner decision — SmartScreen will warn on
first run ("more info → run anyway"); this is reputation, not detection.
The deferred advisory-key rotation remains in force until the owner
calls for it. Self-update: leave the app running — it checks on start
and every six hours, verifies against the built-in key, and restarts to
install.
